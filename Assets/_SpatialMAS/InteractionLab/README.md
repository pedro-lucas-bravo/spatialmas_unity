# SpatialMAS Interaction Lab

This is an opt-in port of `helping_sources/laser-xr/Assets/Scenes/MR_HandsInteraction.unity`, not a reconstructed demonstration. The source and imported scene are byte-identical (SHA256 `77de18a272c7fe74e9b9c836e580b4341bdf1c1405b36638ef8407d5655db74d`). The rig, scene objects, 10 cm comparison cubes, prefab overrides, materials, hand visuals, and serialized interaction settings come from that scene. All distances are metres; no rig scaling or coordinate conversion changes are introduced.

## Open and build

Use **SpatialMAS > Interaction Lab > Open ported MR Hands Interaction**. The menu first offers to save modified scenes. No automatic scene opening or main-scene generation is performed by this lab.

Use **SpatialMAS > Interaction Lab > Build isolated Android APK** after configuring the project's Android/OpenXR settings. The helper builds the persistent Unity 6 Interaction Lab Android profile through `BuildPlayerWithProfileOptions`, leaving `EditorBuildSettings.scenes` intact. Output defaults to `Builds/InteractionLab/SpatialMAS_InteractionLab.apk`. The Android application identifier is temporarily `com.spatialmas.interactionlab`, allowing installation beside the production app. Application identifier, active profile, Gradle user-home preference, and app-bundle preference are restored in `finally`, including on build failure. The helper uses the existing XR and player configuration; it does not run the production scene builder.

**Build Profiles > Ensure Android profiles** creates `BuildProfiles/InteractionLab_Android.asset` and `BuildProfiles/Swarmalators_Android.asset` in this subtree. Each overrides the global scene list with its respective single scene. The two **Select** menu commands expose them in Unity 6's Build Profiles workflow. Profiles are created with the installed Android platform GUID, using the same public API as the reference project's `MetaQuestBuildProfileHelper`.

Use Unity 6000.6.6f1's installed Android SDK, NDK, and OpenJDK in External Tools. The build helper scopes Unity's supported `AndroidExternalToolsSettings.Gradle.userHomePath` to `%USERPROFILE%/.smg`. This avoids a stale global `org.gradle.java.home` without editing the user's Gradle properties. The coordinator may prepare checked `caches` and `wrapper` directory junctions from this dedicated home to existing Gradle caches to reuse downloaded dependencies; the helper does not create junctions, change global toolchain files, or install tools. Actual Gradle execution must verify the selected integrated toolchain and scoped user-home behavior.

Batch method: `SpatialMAS.InteractionLab.Editor.InteractionLabEditor.BuildAndroidApk`. Optional command argument: `-interactionLabApk <output.apk>`. The coordinator must serialize Unity imports, compilation, builds, and device use.

**Build Swarmalators Android test APK** / `BuildMainAndroidApk` builds only `SpatialMAS_Main.unity` to `Builds/InteractionLab/SpatialMAS_Swarmalators.apk` with temporary identifier `com.spatialmas.pickingtest`. It uses the existing main-scene startup configuration; choose Swarmalators from the app menu. This helper also restores the original identifier and app-bundle preference. Both helpers write `Running`, then `Succeeded`/`Failed`, scene/output/identifier, duration, byte count, and errors to `Logs/PickingIteration/InteractionLab_AndroidBuild.json` and `Swarmalators_AndroidBuild.json`, respectively. These files can be polled when builds are scheduled through `EditorApplication.delayCall`.

The manifest provider requests Quest hand-tracking permission/support, `HIGH` frequency, and `V2.0`. These are manifest requests, not guarantees of a particular device sampling rate. It supplies requirements to OpenXR Android builds in this project, including the production build.

## Deliberate adaptations

- `MRCubeInteraction` defaults its added `m_InstantSummon` field to true. Distant direct-attract selections reset the ray attachment offset and place the grabbed attachment at the physical hand in the selection callback. Disable the field in the Inspector to compare the original 10 m/s timed attraction. The gold pull-tether comparison cube retains its separate original modality. Near-contact, palm/pinch hysteresis, release damping, and two-hand behavior retain the reference implementation.
- `MRSimulatorAutoHand` runs before the SDK simulator lifecycle and preserves physical HMD devices. It deactivates the simulator on native players and whenever an Editor hardware XR loader owns the session, including while Link connects or the headset is unworn. Presence alone is not a sufficient guard. Desktop simulation remains available without an active hardware loader.
- `MRPerformanceOptimizer` applies the shared SpatialMAS URP ray material during setup, including inactive hand/controller visuals. This replaces the legacy built-in particle material that produced inconsistent stereo feedback through Link. The original stabilized pinch visual origin is retained. The port therefore uses the production `XRInteractionRigSetup.ConfigureRayVisualMaterial` helper and Resources material, without importing production simulation or recording behavior.
- Two simulator UI sprite references were already dangling in the source and installed XRI sample (`25a7ddcf659944c8d89baff5fcdf9d2e`, `ac2724ca4693e43b8b66f8ef01bd8e3c`). The copied simulator prefab sets these four optional Image sprite fields to null. The scene itself is untouched. Three other simulator gesture icons are recovered from installed package samples with their original GUIDs.
- Runtime sample assembly definitions are preserved so XR Hands/OpenXR version defines enable the same sample code paths. Source namespaces and asset GUIDs are retained. The existing project's hand model assets are reused by GUID rather than copied again.

## Provenance and verification

`provenance.json` records every copied asset's original SHA256 and ported SHA256, plus GUID references resolved to existing project/package assets. Its `unresolvedGuids` field records the two original upstream icon defects described above; those references are null in the adapted output. The dependency set is 154 assets, approximately 39 MB, rather than the full laser project. Folder metas are Unity-generated; copied file metas retain source GUIDs.

Run `python Assets/_SpatialMAS/InteractionLab/Tools/port_reference.py` from the repository root to regenerate the port. Python 3 and `rg` are required; the script launches no Unity process. It traverses serialized GUID references and source-symbol dependencies, explicitly includes the Resources-loaded overlay material, resolves package runtime dependencies externally, copies needed package sample assets to importable folders, applies the listed adaptations, and rewrites provenance. Regeneration overwrites the lab's imported files; save deliberate local experiments elsewhere first.

Performed outside Unity: dependency graph extraction; package GUID lookup; source/scene SHA256 comparison; scan of the imported subtree for Git LFS pointer payloads (none found). The Unity validation menu checks scene presence and Unity's reported dependency paths. Compilation, Android build, missing-component inspection, passthrough/native hand-mesh rendering, near contact, far summon, Link input arbitration, two-hand transforms, release behavior, and headset comfort require coordinator/device verification; this document does not claim they have passed.

Production coordinate, native DSP, and recording contracts are outside this subtree. The reference shader retains GUID `c4fa1c1573064882bead2b200ab98050`, allowing the production overlay material to reuse it without duplicating the shader.
